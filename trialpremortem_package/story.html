01 / THE PROBLEM

The failure is expensive, common, and predictable.

Trials don't mostly fail because the science is wrong. They fail because the design was wrong — and the most common design error is building a trial that cannot recruit.

Here's the part that makes this a real problem and not a competence gap: protocols already get 5–7 expert review passes and still fail this often. The reason is structural. No human reviewer carries the base rates of the thousands of similar trials that came before — and the feedback loop between a design choice and its consequence is broken by time.

02 / THE INTUITION

What if a reviewer could remember every trial that came before?

That's the whole bet. A first draft is just a set of design choices. Thousands of past trials made similar choices — and we know what happened to them. So we should be able to read a draft and say, from precedent alone, whether it will struggle to recruit.

The clever part isn't the model. It's the test: we don't validate against opinions — we validate against history that already happened.

ClinicalTrials.gov keeps the full version history of every registered trial. That let us build a time machine: recover a trial's original first draft, hide everything that happened after, make the model predict, and then check the model against the real recorded outcome. No leakage, no hindsight — a genuine retrospective backtest.

The backtest, in four moves
01 RECOVER

Get the v0 draft

Pull the original first-registered snapshot from version history — outcome-blind by construction.

02 HIDE

Blank the outcome

Drop anything that leaks the ending — including achieved enrollment (a consequence, not an input).

03 PREDICT

Score the draft

The engine rates accrual-failure risk from design features relative to peer trials.

04 CHECK

Grade vs reality

Compare the prediction to what the record says actually happened. Repeat over 927 trials.

03 / HOW WE BUILT IT

Five data/ML layers build a risk engine. An agent uses it as a tool.

The engine is the accuracy floor; the agent is the reasoning and the interface. Crucially, the validated model is a tool the agent calls — not a thing the agent replaces.

L1 · INGEST

Recover drafts

CT.gov v2 API + version history → each trial's v0 draft + amendment trajectory.

L2 · LABEL

Why it stopped

Free-text stop reason → failure class. Positive class = accrual termination.

L3 · EXTRACT

Design features

~25 features incl. restrictiveness & how it compares to ~7,000 peer trials.

L4 · PREDICT

numpy gradient-boosted trees → calibrated accrual-risk + human-readable drivers.

L5 · EVAL

Leave-one-out ROC / PR / calibration + the C0/C1/C2 ablation.

the signal is real

It's in the eligibility

Restrictiveness (p≈0.007), exclusion count (p≈0.003) and comorbidity exclusions (p≈0.004) separate failures from matched controls — exactly where theory predicts.

dependency-light

numpy only, no sklearn

Gradient-boosted trees, BM25 + RRF retrieval and isotonic calibration all implemented by hand — the whole engine is portable and inspectable.

genuinely agentic

It chooses its own path

Each hypothesis gets its own ReAct loop; the agent decides which of ChEMBL / Open Targets / PubMed / CT.gov to call, and when. Not a fixed prompt pipeline.

04 / KEEPING OURSELVES HONEST

The hard part wasn't building it. It was not fooling ourselves.

Every impressive number we first saw turned out to have a leak or a bug behind it. Finding and killing those is most of what makes the result trustworthy.

The one that mattered most — the enrollment leak
0.82
used achieved enrollment — a consequence of failure
→
0.67
honest: v0 draft only, achieved enrollment dropped

For terminated trials the API returns actual enrollment (e.g. "4 patients"). Using it leaks the outcome into the prediction. We caught it, dropped it, and ship the true 0.67 over the fake 0.82.

Rank-based AUCfixed

Trapezoidal AUC mishandles tied/binary predictors and gave a spurious 0.806. We switched to a rank-based (Mann-Whitney) computation with proper tie handling.

The citation gatebuilt

LLMs invent plausible PMIDs. Every id in the register is captured from real tool output; anything the model typed but no tool returned is stripped. A hard assertion checks zero unverified ids ship.

0-indexed historyfixed

The history API is 0-indexed — /history/0 is the draft. An off-by-one here silently trains you on v1 instead of the first draft. We assert the version index matches.

One dispatcher toolfixed

Exposing ≥2 tool definitions tripped a caching 400. We collapsed all connectors behind a single investigate tool with an action selector — no bug, at any thread size.
